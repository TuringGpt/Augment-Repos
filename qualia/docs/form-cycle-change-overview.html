Form Cycles: from role-only access to ownership-based collaboration.

This page explains the current backend behavior, the target product model, and the practical difference for admins, Form Cycle creators, and assigned users.

Core decisionAssignment means “you may submit answers”. It never means “you may edit this Form Cycle.”
Current roles

Three role model

  • Admin creates and manages Form Cycles.
  • Reviewer can complete an assignment.
  • Viewer exists in the model but has no useful product flow.
Current permissions

Role-based, not owner-based

  • Only admins can create and modify Form Cycles.
  • Any admin can manage any Form Cycle.
  • The original creator is recorded but does not control authorization.
Current blocker

One assignment per cycle

  • Database uniqueness permits one submission per Form Cycle.
  • A second reviewer assignment is rejected.
  • Multi-reviewer QA cannot work correctly.

Role 1

Admin

  • Manages users and account status.
  • Manages every Form Cycle.
  • Views every submission.
Role 2

User / original creator

  • Creates and manages only their own Form Cycles.
  • Assigns users to their own cycles.
  • Reviews submissions to their own cycles.
Assignment

Assigned user

  • Reads published questions.
  • Saves and submits only their own answers.
  • Cannot alter the Form Cycle definition or see other users' answers.
